# Matched continuation with unit observations and finite-win credit

Neither finite wins nor richer observations alone has established reliable Hard
strength. The former produced two frozen development wins in30, both Zerg Air;
the latter passed real full-length update/resource checks but Easy40 remains weak.
Test the combination and allow additional learning, with a simultaneous control
that receives the same additional training. This is a continuation experiment,
not an acceptance claim or a replacement for unit-level final perception.

1. Start both branches from immutable finite-win Easy40 bytes, preserving actor,
   critic, optimizer state, RNG, gamma and all existing context. The control uses
   the same frozen finite source. The candidate appends the validated unit-type/
   spatial encoder and zero input weights/moments, without changing actions,
   micro, reward, horizon or learner settings. Archive sources independently.
2. Run the combined suite and actor/critic probability parity on recorded live
   states. Verify real train/resume/frozen smoke separately from untouched initial
   bytes. Avoid policy-schema mixing and retain migration/source hashes.
3. Train40 additional Easy games per branch, with matching initial attempt offset,
   seeds, maps, race/build order and eight workers. Retain batch checkpoints. The
   first eight games should have identical choices before learning; later policy
   RNG can diverge as rollout lengths change. Report every failure and cutoff.
4. Freeze both models and compare matching Hard development cases. Expand a
   promising candidate to both maps/all five builds/all races. Reserve acceptance
   seeds and keep the existing frozen30 win-rate target. No scripted macro recipes.

The combined source and migration are implemented in a separate archive. Compare checkpoints
rather than picking isolated winning replays as proof of strength. If the
combination remains weak, inspect recorded choices/observed enemy exposure and
execution failures before choosing another intervention.

finite Easy40/migrated bytes, not the smoke models. Source remains frozen during
batches; full curriculum starts only after frozen verification succeeds.
