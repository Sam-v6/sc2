# Reuse experience to strengthen Terran learning

The most practical immediate change is **learning again from compatible past training experience**, alongside ordinary reinforcement learning. Published full-game SC2 successes repeatedly combine useful initialization, structured actions, memory and diverse opponents; their compute requirements prevent treating their headline results as expectations for this CPU-limited bot. A small Self-Imitation Learning experiment can test data reuse without installing a framework, scripting macro strategy or changing perception. It needs a careful return/value audit because successful games contain mistakes, and the existing critic can misidentify useful experience. The implementation now contains isolated loss and training-ledger checks, but **no new fitting, gameplay gain or promotion is established**. Hard remains an intermediate target: the development path should preserve competence while progressing through Harder, VeryHard and Elite, then address multiplayer opponents separately.

## Full-game results favor useful abstractions over copying scale

The original SC2LE work established the environment, seven mini-games and difficult full-game baselines. SMAC instead tests cooperating units in predefined combat scenarios. These are useful sources for perception and micro experiments, but winning their scenarios does not establish economy, technology or full-match competence. **Full-game evidence must remain the acceptance standard.** ([SC2LE](https://arxiv.org/abs/1708.04782), [SMAC](https://arxiv.org/abs/1902.04043))

AlphaStar began with imitation of human games before reinforcement learning and league training. Its preliminary January 2019 account reports 95% against Elite after supervised initialization, followed by thousands of simulator instances,16 TPUs per agent and14 days of league training. Those figures describe that preliminary system, not the final Nature system. Its unit transformer, recurrent core and autoregressive actions address different problems: relations within observations, memory across observations and dependent action arguments. The official code release supplies architectures and offline learning, **not online RL training code**. ([AlphaStar preliminary account](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/), [official release](https://github.com/google-deepmind/alphastar))

HierNet is closer to a tractable built-in-opponent experiment: learned hierarchy and extracted macro-actions trained with PPO. It reports 93% against level 7 and96%/97%/94% against cheating levels 8/9/10, using four GPUs and48 CPU threads. Its restricted military units and small-map settings materially limit transfer to unrestricted Terran. Its later setup uses win/loss rewards; its ablations favor more episodes per update and larger batches. TStarBot1 also learns macro control, while TStarBot2 uses expert hierarchical rules; their results must not be conflated. TStarBot1's distributed collection used 1,920 actors and3,840 CPUs. ([HierNet](https://arxiv.org/html/2209.11553v1), [TStarBots](https://arxiv.org/pdf/1809.07193))

Terran-specific SCC uses imitation followed by PPO with entropy and reference-policy KL regularization. Its smaller imitation dataset contains 4,638 replays, while its strongest supervised setup also uses a larger dataset. Its RL setting is Terran versus Terran on Triton, not an all-race CPU-only result. These studies support competent initialization and diversity, but none establishes a time-to-Elite estimate for this machine. ([SCC](https://proceedings.mlr.press/v139/wang21v/wang21v.pdf))

## Self-imitation gives existing training data another purpose

**Behavior cloning, SIL and PPO are distinct.** Cloning minimizes cross-entropy against recorded actions, regardless of whether a particular action helped. PPO improves a policy using freshly collected behavior data and a clipped probability-ratio objective. SIL adds a separate replay loss using historical episodic returns and the current critic. Replaying arbitrary old advantages through the ordinary PPO path would violate the intended data contract. ([PPO](https://arxiv.org/pdf/1707.06347), [SIL](https://proceedings.mlr.press/v80/oh18b/oh18b.pdf))

For a recorded state/action/return triple, define `Aplus=max(R−Vcurrent(s),0)`. SIL uses `Lactor=−log π(a|s)·stop_gradient(Aplus)` and `Lvalue=.5·Aplus²`. Only positive residuals contribute. The paper prioritizes replay by that residual and requires no behavior-policy importance ratio for this distinct objective. The author's code stops the actor weight gradient and includes importance weights for **biased replay sampling**, a separate issue. The published experiments are Atari/A2C and MuJoCo/PPO; there is no demonstrated full-SC2 improvement. Our initial uniform replay adaptation deliberately omits prioritization and uses an ordinary mean. ([SIL equations 1–3](https://proceedings.mlr.press/v80/oh18b/oh18b.pdf), [author implementation](https://raw.githubusercontent.com/junhyukoh/self-imitation-learning/master/baselines/common/self_imitation.py))

The immediate implementation should retain all compatible completed **training** outcomes, rather than cloning only wins. Good portions of losses can contribute; useless actions in victories should not receive automatic expert labels. Return and value must share reward version, scaling, discount, cadence and observation/action schema. The actor must use each recorded actual legal mask. SIL weights must not be centered into negative values, and historical stored advantages must not substitute for the current critic. These are implementation deductions from the objective, not claims that its filter proves causality.

A read-only inventory found 80 Easy training games across the two compatible archive directories, including 26 victories. Their action ledgers and behavior checkpoints provide a feasible starting point even when per-game candidates were cleaned up. The new isolated uniform loss and strict ledger reconstruction each have three passing checks. The completed zero-update audit covers 77,763 transitions:13,157 (16.919%) have positive current advantage. Support spans all races but concentrates on wait 6,767, attack 1,980 and retreat 1,678; Marine contributes 695, Marauder 53, Tank 6 and Starport 2, with no expansion or Battlecruiser support. All 272 inputs were hashed before parsing and rechecked at the end. All 77,763 original sampled choices replayed exactly from immutable behavior checkpoints and recorded policy seeds, with the parent unchanged; independent foundation review remains pending. Earlier audit versions are preserved but have provenance gaps and cannot support fitting. This is feasibility evidence and a warning: replay does not automatically supply advanced strategy. ## Rank data reuse first and richer perception next

**First priority: one bounded PPO+SIL experiment**, conditional on a useful audited corpus. Preserve the retained parent, freeze training inputs, and choose one fixed update schedule using training-only scale diagnostics. Do not search coefficients against protected gameplay labels. Measure fresh sampled behavior as well as greedy behavior: a strong greedy actor can still collect ineffective exploratory games. Compare an ordinary PPO control and the replay-augmented learner on equal training exposure, then immutable policies on an independent balanced panel. Loss reduction or preserved parent KL is insufficient.

Cloning successful self-generated training games remains a possible bootstrap comparison, but should be labeled supervised learning. Human replays offer strategies absent from our archives, yet require player-perspective filtering and mapping raw commands to our macro interface. AlphaStar Unplugged finds that top-quality filtering alone sacrifices diversity, reinforcing the need to avoid a narrow winner-only archive. Scripted teachers would introduce explicit human strategic knowledge and require separate disclosure. ([AlphaStar Unplugged](https://arxiv.org/html/2308.03526))

**Second priority: diagnose history and unit relationships**, then implement the missing information. The current feedforward policy summarizes unit types and spatial cells; it does not retain attributed tokens or recurrent state. A small recurrent core could remember previously observed threats and recent commitments, but needs ordered sequence training and episode resets. A bounded per-unit encoder with pooling could retain type, health, position and order together without immediately adopting full attention. These are CPU-oriented proposals inspired by published architectures, not demonstrated improvements here. ([Current actor](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/src/rl/actor_critic.py>), [current unit encoder](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/src/rl/unit_observation.py>), [AlphaStar encoders](https://raw.githubusercontent.com/google-deepmind/alphastar/main/alphastar/architectures/standard/encoders.py))

The local failures constrain what to repeat. Adding 35 production inputs improved a predictor but regressed frozen Medium play from 22/30 parent wins to 6/30; the corrected optimizer-age follow-up scored 7/30. Collection learning improved resources yet produced no army in its 12 Hard transfer games. Five-second unit intent also failed its gameplay checks, and combined kill/collection rewards scored 0/12 Hard against 4/12 for the parent. Therefore another scalar append, reward mixture or slower action loop needs a new mechanism argument. The unfinished longer-saving probe is deferred; it has no native-game evidence. ([Experiment ledger](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/experiment-results.md>))

## Advance difficulty by competence and retain earlier skills

**Third priority: a full-game opponent curriculum after viable sampled behavior.** Keep the combat objective consistent while mixing the current frontier with previously mastered opponents. The failed collection-only curriculum changed the task; it does not refute difficulty progression on the same task. Use frozen race/build/map panels and check forgetting at each promotion. Hard→Harder→VeryHard→Elite should follow demonstrated per-race competence, not an automatic step every 40 games. Cheating opponents change the problem and warrant separate reporting.

Published leagues preserve strategic diversity, but copying their machinery now would be expensive. TStarBot-X reports 144 GPUs,13,440 CPU cores and25.7 million matches across 57 days. A small fixed built-in-opponent panel is the affordable first analogue; historical learned opponents and exploiters belong after reliable built-in competence. Macro selection remains learned throughout: primitives execute chosen commands without supplying build orders, unit quotas or attack timing. ([TStarBot-X](https://arxiv.org/html/2011.13729))

Each promising method deserves a declared meaningful budget, while each failed bound remains closed. Preserve raw replays, source/checkpoint hashes, actual optimizer counts and native results. Record lost parent wins alongside gains, and keep the reserved final bank untouched until development choices end. The user's 80% CPU ceiling and four-engine cap remain operational constraints; published throughput is no substitute for local measurements.

## Evidence should determine the next expansion

The literature changes the immediate question from “which reward or network knob should we try next?” to “can the learner retain useful full-game experience while collecting competent new experience?” A positive answer supports a controlled difficulty progression. A negative answer directs investigation toward history, action expressiveness or execution bottlenecks, without claiming that statistics-only perception is the final architecture.

This review supplies an implementation order and measurable hypotheses. It does not establish stronger gameplay, reliable Hard performance or eventual ladder readiness. Those claims require independently frozen full-game evidence across the intended opponents.
