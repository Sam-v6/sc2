# Full-game SC2 representations, action abstraction, and credit assignment

## What do primary full-game results actually establish?

### Takeaway

Successful full-game agents combine an appropriate action interface with learning machinery and substantial data. Their results support investigating memory and structured actions; they do not establish that copying a transformer or adding more scalar inputs will improve this bot.

### Cited Findings

- **SC2LE is an environment and baseline, not a solved full-game benchmark.** Its original paper introduces partial observation, large action spaces, replay data and seven mini-games. The baseline agents make progress on mini-games but do not make significant progress on the full game. Treat a CollectMineralShards or BuildMarines result as task-specific evidence. [SC2LE paper](https://arxiv.org/abs/1708.04782), [official PySC2](https://github.com/google-deepmind/pysc2).
- **SMAC is a different learning problem.** Each agent controls one unit in predefined decentralized combat scenarios. It does not learn a full economy, construction, tech progression and match strategy. Its maintainers also warn that SC2 engine versions affect comparisons. Micro methods can motivate controlled combat fixtures, but a SMAC win rate is not evidence of full-game Hard or Elite strength. [SMAC paper](https://arxiv.org/abs/1902.04043), [official SMAC repository](https://github.com/oxwhirl/smac).
- **TStarBot1 demonstrates learned full-game macro control with rules underneath.** Its 165 Zerg macro actions cover construction, production, research, resources and 100 region-to-region combat choices. Placement, subject selection, prerequisites and hit-and-run execution include rules. Observations include scalar statistics, spatial counts and recent actions; networks are MLPs. Its terminal-only reward is win/tie/loss. The distributed rollout system uses 1,920 actors and 3,840 CPUs across 80 machines. TStarBot2's hierarchical controllers are expert rules, so its performance must not be presented as learned hierarchy evidence. [TStarBots paper, sections 3.2–3.3](https://arxiv.org/pdf/1809.07193). The author release exposes more than 100 discrete macro actions and example DDQN/PPO infrastructure. [TStarBot1 author code](https://github.com/Tencent/TStarBot1).
- **HierNet supplies genuinely learned hierarchy, within a particular experimental setup.** A slower controller selects subpolicies; lower-level policies select macros, with rewards accumulated over the controller interval. The extended paper uses restricted unit/action setups and reports strong built-in-bot results, so those results should not be treated as unrestricted Terran generalization. [HierNet extended paper](https://arxiv.org/pdf/2209.11553). The authors release training code, logs, models and expert replay data. [Author repository](https://github.com/liuruoze/HierNet-SC2). The actual mining script calls PrefixSpan, takes the top 75 patterns, and constrains sequences to start with selection and avoid repeated operations. This is selection/command abstraction, not evidence that arbitrary long build-order scripts should be added. [Author macro-mining implementation](https://raw.githubusercontent.com/liuruoze/HierNet-SC2/main/mine_from_replay.py).

### Inferences

- Retaining legal atomic primitives is consistent with successful full-game work. A learned macro controller can delegate reliable mechanical execution without delegating its strategic choices. TStarBot's region-based combat interface is materially richer than a single whole-army attack/retreat bit; the literature motivates inspecting missing choices, not automatically adding its entire action catalogue. [TStarBots action definitions](https://arxiv.org/pdf/1809.07193).

### Gaps

- These papers do not provide a clean architecture-only comparison under this project's CPU budget, Terran primitives, opponent schedules and retained parent. Published cheating-bot results are also not interchangeable with this repository's held-out per-race acceptance test. [TStarBots](https://arxiv.org/abs/1809.07193), [HierNet](https://arxiv.org/abs/2209.11553).

## What would memory, entity encoders and autoregressive actions change here?

### Takeaway

Memory addresses information lost over time; entity encoders address relationships lost within a snapshot; action factorization addresses choices lost in the interface. They are separate interventions and should not be bundled.

### Cited Findings

- **AlphaStar's full-game architecture combines these mechanisms.** The authors describe a transformer over unit lists, an LSTM core, autoregressive action generation, pointer selections and a centralized critic. [Official AlphaStar account](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/).
- **The released architecture makes conditioning concrete.** A sampled function/argument is embedded back into the vector stream, conditioning later heads. Unit selection and target selection use pointer logits with different eligibility masks. This is more than independently predicting several categorical outputs. [Official head implementation](https://raw.githubusercontent.com/google-deepmind/alphastar/main/alphastar/architectures/standard/heads.py).
- **The released observation encoder keeps several modalities.** It separately encodes raw units, count/statistic vectors, requested and observed races, previous action arguments, and minimap visibility/pathability/buildability channels. [Official encoder implementation](https://raw.githubusercontent.com/google-deepmind/alphastar/main/alphastar/architectures/standard/encoders.py). The repository supplies architectures and offline learning tools, explicitly excluding online RL training code; the release is not a drop-in reconstruction of the original league learner. [Official release scope](https://github.com/google-deepmind/alphastar).
- **TStarBot-X also combines unit transformers, a central LSTM and autoregressive/pointer heads.** Its observation uses visible unit attributes, spatial/scalar state, previous actions and masks. Its training critic can use privileged enemy information; that must not leak into an evaluation actor. It explicitly discusses quadratic unit-attention cost and an unsuccessful spatial scatter/gather substitute. Its reported formal run uses 144 V100 GPUs, 13,440 CPU cores and 57 days. It also conditions training on human build-order/statistic targets, so its strength is not an isolated memory experiment. [TStarBot-X paper](https://arxiv.org/html/2011.13729). Author implementations are linked through [TPolicies](https://github.com/tencent-ailab/TPolicies) and [Arena](https://github.com/tencent-ailab/Arena).
- **The current bot is feedforward.** Its actor/value forward pass is a single tanh hidden representation; its unit encoder separately summarizes unit identities and coarse spatial cells, rather than maintaining one attributed token per unit. [Current actor](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/src/rl/actor_critic.py>), [current unit encoder](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/src/rl/unit_observation.py>).

### Inferences

- A small recurrent core could remember an earlier observed enemy composition, recent failed expenditure, or an intended investment while the current visible snapshot changes. It cannot recover enemy facts never observed. A useful prerequisite is a frozen-state/history diagnostic showing conflicting decisions for similar current observations but different histories. Recurrence changes training contracts: complete sequence order, episode reset, sequence masks and reconstructed hidden state become essential. Shuffling independent transitions into a recurrent PPO learner would lose the intended conditioning. This inference follows from the architecture's explicit history dependence. [AlphaStar account](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/).
- A bounded shared per-unit MLP plus pooling could preserve type, position, health, build progress and order features together, with linear work in token count. This is a CPU-oriented inference, not a published SC2 performance claim. Full attention is a later option if interactions require it; its pairwise work grows quadratically. The present counts/grids can alias distinct unit arrangements. [Current encoder](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/src/rl/unit_observation.py>), [TStarBot-X architecture discussion](https://arxiv.org/html/2011.13729).
- Raw autoregressive function/producer/target/location heads greatly enlarge what the policy can control, but also expand legal-mask, likelihood and rollout-schema requirements. Start only with an identified consequential missing argument—such as learned rally region—rather than copying hundreds of raw actions. Existing primitives already solve many producer/placement details. [AlphaStar head implementation](https://raw.githubusercontent.com/google-deepmind/alphastar/main/alphastar/architectures/standard/heads.py), [current executor](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/src/rl/terran.py>).

### Gaps

- No source examined establishes a practical recurrent/entity model size or training budget for this four-client CPU setting. Parameter counts or asymptotic operation counts do not measure SC2 throughput; benchmark encoding, inference, training and engine wall time separately. [TStarBots rollout bottleneck](https://arxiv.org/pdf/1809.07193).
- TPolicies/Arena release existence was verified; a complete file-by-file reproduction of their preprocessing and recurrent learner was outside this bounded review. HierNet's macro-mining code and AlphaStar's encoder/head code were directly inspected. [TPolicies](https://github.com/tencent-ailab/TPolicies), [HierNet mining code](https://raw.githubusercontent.com/liuruoze/HierNet-SC2/main/mine_from_replay.py).

## Which next step avoids repeating failed local arms?

### Takeaway

A bounded training-only self-imitation diagnostic is a reasonable immediate priority because it preserves the current interface and tests whether useful existing experience is being discarded. Memory and stronger action commitment remain defensible later hypotheses, rather than conclusions from the literature.

### Cited Findings

- Adding 35 verified production-state inputs passed an information-prediction gate but regressed frozen Medium play: parent 22/30, matched old-input control 21/30, sensory 6/30. Resetting the appended rows' Adam ages reduced first-update disturbance but yielded 7/30. More observable detail alone therefore has already failed a matched gameplay test. [Sensory experiment](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-05-production-sensory-learning.md>), [fresh-age follow-up](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-05-production-input-fresh-adam.md>).
- Five-second pending unit intent also failed: its two frozen Hard banks produced zero victories; matched immediate control produced zero and one. Unit diversity was not evidence that persistence improved strength. [Completed unit-intent ledger](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-04-unit-intent-experiment.md>).
- The current saving foundation tests a different mechanism: sustaining a resource commitment up to a bounded release, with a matched wait control and native physical completion requirements. It is not completed runtime evidence. [Saving probe declaration](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-05-resource-saving-probe.md>).
- The newly declared SIL adaptation uses completed compatible training episodes, current positive advantages, uniform replay means and a separate loss; evaluation victories are excluded. It expressly labels omission of prioritized replay and does not claim SC2 transfer from Atari/MuJoCo evidence. [Local SIL declaration](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-05-self-imitation.md>), [original SIL paper](https://proceedings.mlr.press/v80/oh18b.html).

### Inferences

- **SIL-first is reasonable as a mechanism test, not a promised improvement.** Audit whether compatible training data supplies positive current advantage for useful economy/combat actions, and measure actor/value gradient scales and parent KL before a bounded fit. This preserves representation, action space and reward, making the result easier to interpret than simultaneous recurrence/entity/options changes. An empty or highly concentrated support set is a legitimate stop condition. [Declared SIL scope](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-05-self-imitation.md>).
- If SIL cannot preserve useful behavior, investigate temporal aliasing and sustained commitment separately. Hierarchical macros are most relevant when they remove a demonstrated planning/execution bottleneck; merely slowing every action or adding pending labels repeats the closed five-second experiment. A saving option also needs explicit initiation, termination, interruption and elapsed-time reward/discount semantics; changing the decision unit changes the credit problem. [Unit-intent closure](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-04-unit-intent-experiment.md>), [HierNet controller formulation](https://arxiv.org/pdf/2209.11553).

### Gaps

- This review does not determine whether data reuse, memory, spatial capability or sustained investment is the dominant current limitation. None of the cited systems provides causal evidence for that ranking in this bot. A successful local derivative, prediction task or mini-game must still be followed by independent frozen full-game evidence before calling it playing-strength progress. [Local sensory counterexample](</home/sam/repos/sc2-repos/sc2-void-bot/.worktrees/terran-rl/docs/superpowers/plans/2026-10-05-production-sensory-learning.md>).
